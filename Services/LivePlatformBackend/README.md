# Live platform backend

This independent Python service implements the [client contract](../../docs/integration/live-backend-contract-v1.md): official launch-token/room/anchor verification, private 12-hour backend bearer sessions, durable round accounting, weekly totals and ordered world-rank delivery. It does not replace the SDK's comment/like/gift push path. No real credential or deployment is included.

The user-confirmed policy accumulates final personal scores, counts wins, increments consecutive wins and clears them on a loss. Gray users receive zero metrics and are absent from world totals. Weeks reset Sunday 23:00 Asia/Hong_Kong. The week is determined by the **first successful server receipt**, so a completed round delayed over cutoff counts in the new receiving week. `late=true` / `operator_state=late_round_received_current_week` preserves that audit fact without excluding its score or uploads. Ties in score use stable open_id order. Within the receiving week, the participant sequence is recomputed by `(end_time,room_id,round_id)`. A cross-week retry returns its original stored receipt/week and never counts again; derived week is excluded from submitted-content equivalence. Future timestamps crossing an actual week boundary return retriable 503 until the server reaches it, preventing premature version activation.

## Windows + existing IIS deployment

The target described by the user is a Windows Tencent server in Shanghai, 2 cores / 4 GB, with IIS and `https://example.com/`. The actual server, its existing business, certificates, URL Rewrite and ARR installation have not been inspected. Deployment has not been executed. No Linux Docker Desktop installation is required.

1. Place this service outside all website physical roots, for example `C:\Services\LivePlatformBackend`. Place its SQLite database on a persistent local NTFS data directory such as `C:\ProgramData\GeometricWarfare`. Never expose source, `.env`, database, WAL or backups through IIS. Give only the service account and backup operator the needed filesystem access.
2. Install Python 3.12 for the service account. From the service directory, run `py -3.12 -m venv .venv` and `.venv\Scripts\python.exe -m pip install -r requirements.lock.txt`. The versions actually tested locally are Python 3.12.14, FastAPI 0.142.2 and uvicorn 0.54.0; the lock includes the resolved runtime dependencies.
3. Copy `.env.example` to a server-only `.env`. Populate `BACKEND_APP_SECRET` on that server, not in UE/host/client packages. `BACKEND_ONLINE_VERSION=false` separates debug data; changing it is an explicit deployment decision. Boolean values must be exactly true/false (case-insensitive); typos abort startup. Keep `BACKEND_ENABLE_UPLOADS=false` until credentials, scope and wire validation are ready. Empty AppSecret makes session exchange unavailable rather than using a simulated identity.
4. Start with `powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Services\LivePlatformBackend\Start-Backend.ps1`. The script only reads its supplied environment file and starts this process. It does not register services, alter firewall/IIS, install modules or modify websites. It binds **127.0.0.1:8765**, fixes **one uvicorn process**, and disables access logging. Use an operator-approved Windows service wrapper or scheduled-task supervision for restart/reboot persistence; registration and service-account permissions remain a deployment action.
5. Run `Preflight-IIS.ps1` on the server as a read-only module inventory. URL Rewrite + ARR must be present; the operator must explicitly enable ARR proxy and allow `HTTP_X_FORWARDED_PROTO` for the intended rule. `iis-live-api-merge.fragment.xml` is a **merge fragment**, never a replacement web.config. Merge only its `live-api` rule and scoped request limit into the existing site's configuration after inspection/backup. It routes only HTTPS `/live-api/...` to the loopback backend, sets forwarded protocol to `https`, strips the public prefix and limits requests to **4 MiB** for that path. Do not silently change global proxy permissions or unrelated routes. Existing HTTP-to-HTTPS policy is outside this fragment.
6. uvicorn trusts forwarded headers only from **127.0.0.1**. ARR must send the verified HTTPS protocol; a client-supplied forwarded header must not stand in for this rule. Keep `BACKEND_ALLOW_LOOPBACK_HTTP=false` in production. Only explicit development configuration admits loopback plaintext authentication; remote plaintext is always denied. `/healthz` exposes non-secret status and permits local health probes.
7. After verifying TLS/proxy behavior, the SDK host's site base is `https://example.com/live-api`. It appends `/v1/douyin/sessions` and `/rounds`. Backend requests are capped at 4 MiB; enriched responses for 5000 valid participants fit the host's separate 2 MiB response bound.

IIS references: [Microsoft reverse proxy with URL Rewrite and ARR](https://learn.microsoft.com/en-us/iis/extensions/url-rewrite-module/reverse-proxy-with-url-rewrite-v2-and-application-request-routing), [requestLimits bytes](https://learn.microsoft.com/en-us/iis/configuration/system.webServer/security/requestFiltering/requestLimits/).

## Persistence and delivery

SQLite WAL is the initial single-host persistent adapter behind `Repository`. Archive, receipt, recalculated totals and immutable upload work commit in one `BEGIN IMMEDIATE` transaction. IDs and scores are never converted through float. App, test/online environment, room and round isolate identity; different content for an existing round returns 409. Backend credentials are stored only as SHA-256 digests. Application and launch tokens are not stored or logged.

Run **one service instance and one upload worker** for each application/environment. A local OS file lock prevents another service process using the same database path from starting its uploader. Do not run multiple processes/machines with separate database copies or more uvicorn workers. Lease tokens protect database completion/retry state; they cannot cancel a write already sent to Douyin and are not distributed upstream fencing. A crashed process may retry the same absolute snapshot; current single-worker sequencing prevents subsequent snapshots overtaking that retry. Future cloud scaling requires a reviewed shared-database/delivery design.

Each publication uploads all accumulated users in batches of at most 50, then one explicitly sorted Top150. Full user refresh also updates rank for participants whose score did not change. It has a deliberate queue/bandwidth cost: 5000 cumulative users produce 100 user batches plus one list job. The uploader uses a conservative two requests/second, below the documented per-operation limits; backlog must be monitored. It is not a claimed capacity measurement for the 2-core Tencent server.

On cutoff the service seals old local data, enqueues a final complete user/list snapshot, then old-version completion, then the next active version. Transient network/token/rate errors retain the same body with bounded exponential backoff. Terminal rejections and out-of-range Int64 publication values remain failed for diagnosis and block later overwrites. Weekly sums stay exact locally even if greater than Int64; they are never silently clamped or sent as illegal platform integers. `/healthz` exposes outbox state and configuration blockers without bodies or credentials.

The official world `complete_time` contract proves Int64 but does **not** establish seconds versus milliseconds. `BACKEND_COMPLETE_TIME_UNIT` intentionally defaults empty. Set it to `seconds` or `milliseconds` only after platform confirmation. Missing unit pauses that complete job and subsequent version switching, while new-week archives/aggregation remain available. This is distinct from application-token refresh: server app tokens are cached/refetched from the actual credential endpoint; no platform launch-token refresh endpoint is invented. Backend session TTL does not prove the broadcaster remains live or extend the platform's authorization.

Use the Python SQLite backup API via `python -m live_backend.operator --database C:\ProgramData\GeometricWarfare\live-backend.sqlite3 backup <outside-webroot-destination>` for a consistent online backup, including WAL state. Do not copy only a live `.sqlite3` file and lose WAL transactions. Keep backups on separately protected persistent storage, exercise restore in an isolated environment, and define retention before production. With the same `--database` option, `status` reports job counters, safe error codes and late-round counts; it does not print auth or payloads. A terminal job is retried only by the explicit local operator command `retry-failed <id>` after the cause is resolved; no public admin endpoint exists. CLI tools use process environment (or explicit database path), not automatic `.env` loading.

## Tests and current boundaries

Install `requirements-dev.txt` in the local test environment, then run `.venv\Scripts\python.exe -m unittest discover -s tests -v`. On this Codex Windows machine the default sandbox prevents the ASGI/thread test loop from progressing; the same full suite runs under the normal permitted Windows process context. Tests use fake room identities and an injected transport, never a real token or secret. Public wire fixtures are included with provenance. Run `benchmark.py` for one local 5000-user archive/duplicate transaction, not a Tencent throughput prediction.

The Dockerfile is an optional future Linux artifact. Its proxy must share the loopback network namespace and `/data` must be a persistent volume. It has not been deployed/built here; Windows production follows the native process/IIS steps above.

Real AppSecret acquisition, platform scopes, cross-app launch-token behavior, live world uploads, completion timestamp unit, IIS/ARR permissions, service supervision, server backups and actual Tencent capacity remain deployment/acceptance checks. Room authentication establishes the server-configured application context and returned room/anchor; the public response has no app_id field. It does not make client-reported scores independently authoritative against a modified client.
