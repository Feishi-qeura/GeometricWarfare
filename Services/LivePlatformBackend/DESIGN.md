# Live platform backend

The service owns trusted room identity, durable round archives, weekly accumulation and world-rank delivery. UE and the local SDK host never receive AppSecret or the application's service access token. Existing comments, likes and gifts remain on the official SDK push path.

Python 3.12 and SQLite are available. The persistence and HTTPS transport layers use the standard library; FastAPI and uvicorn provide a small deployable HTTP layer through explicit dependencies. Unit tests run with `unittest` without web dependencies. Production runs one durable outbox worker per SQLite database; leases also prevent simultaneous workers from claiming the same job. SQLite WAL and short `BEGIN IMMEDIATE` transactions serialize accumulation.

A launch token is submitted over HTTPS to a room-verification adapter using the actual official contract. Only the returned app/room/anchor identity becomes trusted. An opaque service session binds that identity and an expiration; only its digest is stored. Launch tokens, AppSecret and application access tokens are never persisted or logged. No client-supplied room ID or anchor overrides verified identity.

Round archive identity is app + environment + room + round ID. An identical canonical submission is idempotent; a different submission for that identity is a conflict. Archive, user accumulation and delivery jobs commit in one transaction. Rankings are derived on the server from accumulated integer values, not from client-provided cumulative totals. Integer values are stored losslessly as decimal strings and ranked in Python, avoiding SQLite sum overflow and floating-point loss.

Confirmed policy: personal score sums, wins count, consecutive wins reset on loss, gray excluded; Sunday 23:00 Asia/Hong_Kong resets. The first successful backend receipt determines the statistics week. A finished round arriving after cutoff counts in the new receiving week, with a late audit marker. Cross-week duplicates use their original immutable receipt/period and never count twice. The content hash excludes derived period. Within a receiving week, end_time/room_id/numeric round_id order gives deterministic streaks. Future timestamps crossing a still-unreached week boundary return 503 and do not activate a version. The repository supports the explicit server-selected policy; deployment remains unavailable when official authentication credentials are missing.

The durable outbox carries explicit app/environment/version for every world operation. Operations within a publication run have ordered dependencies. Lease tokens fence stale workers; completed jobs cannot be retried or overwritten. Transient failures retain the same immutable body and use bounded exponential backoff. Permanent upstream rejection is visible as a failed job rather than fabricated success. World APIs overwrite data, so snapshots must be published in order: an old retry cannot overwrite a newer snapshot. Archive and cumulative data survive worker/process restarts.

Tests cover duplicate/conflicting rounds, atomic rollback, lossless large integers, session expiration, lease/retry fencing, ordered deliveries and persistence across reopen. HTTP/authentication contract tests use synthetic identities and a local injected transport; no real launch token or secret is needed. Live official acceptance remains a separate deployment check.
