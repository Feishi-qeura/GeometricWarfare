# Douyin SDK host

The Windows companion is a real Unity 2022.3 player using the officially acquired LiveOpenSDK 2.7.12 public `LiveOpenSdk.Instance` entry. UE owns gameplay and rendering. The host does not implement co-play, fans club, linkmic, cloud sync or a private login API.

Run `Build.ps1` after official BGDT acquisition. It copies the SDK and already downloaded Unity dependencies into `tmp/DouyinSdkHostBuild`, never edits the acquisition project, and builds `Plugins/DouyinLiveProvider/Binaries/Win64/SdkHost/DouyinSdkHost.exe`. Ship the complete output directory, including player data, native dependencies and `parfait_crash_handler.exe`. Do not commit or redistribute licensed SDK binaries without checking their terms.

Launch with redirected anonymous stdin/stdout, `-batchmode -nographics -logFile -`. Unity redirects its standard output handle to the selected log target; using `NUL` or a file therefore loses the protocol pipe. Host writes through the Windows inherited stdout handle. Credentials must appear only in the first stdin frame, never arguments or logs. SDK log bodies are not subscribed, and Unity managed logging is disabled before splash/startup. stdout may include Unity native diagnostics: accept only lines beginning `GWSDK/1 `, then parse JSON. Input and output records are bounded to 4 MiB UTF-8 bytes each. Input has independent queues for 256 ordinary commands and 8192 ACKs, with a shared 16 MiB byte limit; output has a 1024 frame / 16 MiB limit and a separate writer so pipe backpressure cannot block the Unity main thread. Each frame drains at most 128 ACKs even while an ordinary SDK call awaits, then processes up to 128 synchronous ordinary completions. Ordinary SDK commands preserve FIFO order; ACK does not release their busy flag. One backend request also runs independently. Continue draining stdout through shutdown to avoid a full pipe blocking exit. `Test-Protocol.ps1` checks local validation without a real token; `Test-InputClose.ps1` verifies graceful stdin EOF; `Test-InputLimit.ps1` checks oversized input rejection. These do not authenticate a live room.

Official Runtime contains an automatic `envs.log` write with inherited environment/path diagnostics and optional performance-file code. There is no confirmed public switch to suppress all SDK-created files; `-logFile -` controls Unity's player log only. Set a dedicated host working directory. The startup credential is exclusively stdin, so this integration does not place it in inherited environment or command-line diagnostics. No SDK private implementation was modified.

The packaged UE entry must use [DouyinLauncher](../DouyinLauncher/README.md) to strip the official platform token before UE startup logging, then UE sends the host's init frame. Forward the validated, nonsecret `-cloud-game`, `-mobile`, `-screen-width`, `-screen-height` key/value integer arguments for SDK environment detection; keep `-screen-fullscreen 0` on this host. SDK's public Runtime caches these arguments. This parameter handling does not certify cloud video delivery.

Input frames contain `op` and caller-chosen string `id`. Operations after initialization also require the current `room_id`:

| op | Additional fields | SDK call |
| --- | --- | --- |
| init | app_id, token, msg_types (optional allowlist), backend_url and allow_insecure_backend (optional) | Initialize(app_id), WaitForRoomInfoAsync, StartPushTaskAsync(type, SinglePush); optional immediate backend session exchange |
| ack | msg_id, msg_type | ReportAck |
| round | round_id, start_time, end_time, status, group_results:[{group_id,result}] | UpdateRoundStatusInfoAsync |
| user_group | round_id, open_id, group_id | UpdateUserGroupInfoAsync |
| user_results | round_id, users (max 50) | UpdateUserRoundListInfoAsync |
| room_rank | round_id, users (max 150, score descending) | UpdateRoundRankListInfoAsync |
| complete | round_id, complete_time | UpdateRoundResultInfoAsync |
| backend_round | round_id and score as decimal strings, start_time/end_time Unix seconds, users:[{open_id,group_id,score,result}] (max 5000) | Our backend `/v1/douyin/rounds`, not a public SDK world-rank call |
| stop | no room required | StopPushTaskAsync, Uninitialize |

`users` elements: `{open_id,rank,result,score,win_points,win_streak,group_id}`. Timestamps for rounds are Unix seconds; message timestamps are Unix milliseconds. Caller persists strictly increasing round IDs per room, uploads all participant results, then the top room ranking, then completion last. Failed SDK operations remain failed; host never fabricates success or silently retries.

Output `kind=room` contains app_id, room_id and anchor `{open_id,nickname,avatar_url}` from SDK room data. `kind=status` contains request_id, op, success, err_code and optional state/data. Positive errors come from SDK round responses or backend HTTP status codes; negative codes are local: -1001 invalid input, -1002 limits, -1003 input failure, -1004 missing credentials, -1005 no authenticated room, -1006 SDK exception/null response, -1007 repeated init, -1008 room timeout, -1009 invalid room, -1010 unacknowledged-event backpressure, -1011 stale room, -1012 backend unconfigured, -1013 invalid/backend transport response, -1014 timeout/cancelled, -1015 backend reauthorization required, -1016 backend busy. No exception/error body is forwarded.

The optional backend channel follows [the service contract](../../docs/integration/live-backend-contract-v1.md). It authenticates immediately after official room discovery, without waiting for the round or blocking SDK push startup. HTTPS is required with default certificate validation; redirects, cookies and proxy inheritance are disabled. A base URL such as `https://example.invalid/live-api` yields `/live-api/v1/douyin/sessions` and `/live-api/v1/douyin/rounds`. Reject URL credentials/query/fragment; explicit development HTTP permits only localhost/127.0.0.1. Each entire operation has a 15-second deadline, including serialized access and any first exchange; response bodies are bounded to 2 MiB.

Session exchange sends the platform launch token only in Authorization, verifies returned app/room/anchor against the SDK, and retains the backend bearer only in host memory. It never sends either bearer to UE. Subsequent rounds use that backend bearer. Expired/rejected sessions require fresh authorization; there is no invented platform token refresh. Room/anchor changes invalidate the cache and queued/in-flight old-generation receipts. Backend `data` contains only verified `{accepted,round_id,world_rank_version,users:[{open_id,win_points,win_streak}]}`; metrics are decimal strings. `backend_accepted` confirms durable local receipt, not world-rank acceptance. A `backend_auth` failure does not invalidate an otherwise authenticated SDK room.

`Test-BackendHttp.ps1` compiles the client with the Unity Mono runtime and verifies fake HTTP replies plus a real temporary loopback-only mock server. It covers source binding, early exchange, 5000 participants, exact Int64 scores, base paths, cached/expired credentials, old-room generation rejection, redirect rejection, declared/streamed response limits, cancellation and sanitized errors. Windows sandbox restrictions may require approval to bind the temporary loopback listener; no real platform or server credentials are used.

`init` success means official room data was obtained. Each subscription returns its own `subscribe:<msg_type>` status. Initialization/subscription failure and token expiration (40004) return state=failed and disable event delivery. `connection` status reports connected/disconnected; only after SDK room authentication and connected push does the host emit room so UE can create its trusted session; reconnection re-emits room. Events include room_id, msg_id, msg_type, timestamp and user. Additional event fields are content, count, gift_id/magic_gift_id/gift_value/is_test/audience_open_id, group_id, follow_action/follow_target, enter_type/enter_scene/follow_status/is_old_player/grade_level/inviter_id. Like/gift `count` is a decimal string preserving full SDK Int64 precision; timestamps remain JSON numbers. Enter type 1 is entering and 2 leaving, verified from official document by the parent task. Follow 1/2/3 means follow/unfollow/follow back.

The build includes Editor contract checks against public SDK interfaces, covering Int64.MaxValue and 2^53+1 counts, follow target string/action, presence keys, and source envelope. Fixtures are Editor-only; the player exposes no test-event injection command. All active command tasks and late room/stop tasks have observed exceptions; SDK error bodies are not printed. Shutdown waits at most 750 ms for push stop tasks and 750 ms to drain queued output before quitting.

The build also executes `Editor/HostSchedulingTests.cs` against the real host `Update` and command handlers using public SDK test doubles. A controlled pending round request receives 600 ACKs, which all call ReportAck before the round completes; a following ordinary command remains queued until completion. Tests verify the 128/frame ACK budget, busy/FIFO isolation, independent 8192/256 count limits, and shared 16 MiB byte bound. Overflow still fails closed; the larger independent ACK lane removes starvation caused by awaiting ordinary SDK requests.

UE sends ACK only after actual application/rendering. Host accepts ACK only for an emitted message in the current room. Since the official ACK method returns void, success with state=submitted confirms the call, not remote acceptance. Real startup token, room events, fulfillment, ranking and platform/cloud deployment still require live testing.

Pending ACKs and submitted ACK history each have an 8192-entry bound. Retrying a matching already submitted ACK returns submitted without calling SDK twice; already submitted replays are suppressed. Both histories are cleared on room change. Platform-review gifts retain `is_test=true`, execute gameplay with isolated entitlements/statistics, and follow the normal post-render ACK path. Unmapped or invalid gifts must not fabricate fulfillment; enough ignored unacknowledged events eventually trigger failed state and require fixing the subscription/configuration.
