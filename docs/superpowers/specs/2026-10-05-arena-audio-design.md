# 几何战争音频设计

日期：2026-10-05。范围：当前 UE5.8 项目新增音频、音量设置与音频压力测试。
用户已确认聊天中的音乐/音效范围、电子街机风格、16 路音效并发预算。
本文件是书面设计，尚未实施，也不代表音乐试听或直播收音验收已完成。

## 目标与风格

与简约几何画面统一：原创合成器、清晰短鼓点、轻微颗粒感，避免写实枪声和冗长混响。
三首主 BGM 使用同一旋律动机和 A 小调/Dorian 调式色彩，通过配器和节奏区分阶段。
音乐为游戏原创合成作品，不依赖下载第三方歌曲，不使用外部生成 API。
素材保存可复现的生成源、制作参数与 WAV，导入 UE 的音频资产随包体发布。

5000 人场景下保持主要反馈可辨识，音频不会为每名玩家创建组件、声音实例或独立更新任务。
音频裁剪仅影响听觉表现，不影响射击、伤害、拾取、积分、事件履约与直播 SDK 通信。

## 音乐：5 段

| 编号 | 用途 | 音乐设计 | 触发与退出 |
| --- | --- | --- | --- |
| M01 Battle | 开局主曲 | 112 BPM，32 小节，约 68.57 秒循环；轻鼓点、弹性低音、明亮短音符 | 新局/战斗阶段，BOSS 未出现或已击败时播放 |
| M02 Boss | BOSS 主曲 | 112 BPM，32 小节，同主旋律改低音区与紧张配器 | BOSS 出现且仍存活；BOSS 死亡回 Battle；冲刺/结算优先覆盖 |
| M03 Sprint | 最后冲刺 | 140 BPM，32 小节，约 54.86 秒循环；更密节奏与上行旋律 | `Phase::Sprint`，沿用现有冲刺阶段，不新增或修改倒计时阈值 |
| M04 Results | 结算曲 | 112 BPM，8 小节，约 17.14 秒循环；主题收束，压低打击乐 | `Phase::Results`；新局退出 |
| M05 HostAssist | 主播助战短曲 | 112 BPM，2 小节，约 4.29 秒，不循环；同主题五角星入场动机 | 第一次成功助战或成功切到不同阵营；重复选择同队不重播 |

主曲切换淡入淡出 0.6 秒，两首同时存在仅限过渡；最多 2 个主曲组件。
助战短曲独立 1 个组件，主曲音量在 0.15 秒内降到原值的 35%，短曲结束后 0.4 秒恢复。
助战短曲有 2 秒重触发冷却；冷却内仍执行有效换队，但不重播短曲；冷却结束后的换队复用同一组件重播，不叠加新的组件。
结算切入立即终止助战短曲，停止战斗持续音，退出压低主曲的状态。
BOSS 击败、跨阶段快进、自动新局、平台会话重置均使用同一个音乐状态选择规则。
所有音乐、淡变、冷却按实际墙钟时间播放；演示倍速只影响模拟，不加速音乐。

| S01 Pistol | 手枪开火 | 短促电子脉冲与小低频冲击 | 子弹成功发射/弹药实际消耗；不以命中为条件 |
| S02 Shotgun | 霰弹枪开火 | 宽噪声冲击，厚于手枪 | 一次开火只记一次，不为每颗弹丸播放 |
| S03 Sniper | 狙击枪开火 | 尖锐起音、低频尾音 | 狙击弹实际发射，不在瞄准阶段播放 |
| S04 Rifle | 步枪开火 | 紧凑金属合成音 | 步枪弹实际发射 |
| S05 MachineGun | 机枪开火 | 短颗粒脉冲，适合密集重复 | 实际发射；聚合后仍保持节奏感 |
| S06 Rocket | 火箭筒开火 | 合成低频冲击加短喷射尾音 | 火箭实际发射；不因后续爆炸重复播放开火声 |
| S07 FighterHit | 几何体受击 | 短玻璃/几何撞击感 | 玩家实际承受正数伤害，包含护甲吸收 |
| S08 FighterDeath | 几何体死亡 | 短下降音阶、碎裂感 | 从存活转为死亡一次；重复伤害不重播 |
| S09 BossBullet | BOSS 弹幕攻击 | 深沉能量弹释放声 | 每次实际弹幕齐射一次；狂暴多弹仍算一次 |
| S10 BossLaser | BOSS 激光攻击 | 蓄力提示与持续电子束 | 蓄力入场、激光激活及退出；同步现有普通/狂暴蓄力长度 |
| S11 BossStomp | BOSS 跳跃踩踏 | 上行蓄能与落地低频冲击 | 跳跃起始提示，进入冲击波时落地声；不逐帧重复 |
| S12 Orb | 小球吸收加分 | 清脆上行短音符 | 球被实际吸收一次；不从飘字数量推断 |
| S13 NpcHit | 中立 NPC 受击 | 较钝的电子撞击 | NPC 承受正数伤害 |
| S14 NpcDeath | 中立 NPC 死亡 | 短破裂下行音 | NPC 从活动转为死亡一次 |
| S15 WeaponPickup | 武器箱拾取 | 清晰机械确认音阶 | 触碰箱体成功获取武器 |
| S16 WeaponBreak | 武器箱打破 | 箱体破裂加获取音阶 | 最后一击打破并获取武器；不再同时叠放 S15 |
| S17 EvolutionPickup | 进化拾取 | 轻盈上行能量音阶 | 触碰成功获得进化 |
| S18 EvolutionBreak | 进化打破 | 能量壳破裂加上行音阶 | 最后一击打破并获得进化；不再同时叠放 S17 |

18 类是逻辑类别，激光蓄力/束流、踩踏提示/落地可使用分开的音频资产。
同类高频短音用少量音高变化（最多 ±4%）避免机械感，变化不用于 BGM、激光持续音和结算提示。
BOSS 死亡、取消蓄力、结算、关音效时停止对应持续音，不遗留无限循环。

## 音频资源与播放

- 制作母版：48 kHz、16-bit PCM WAV；音乐立体声，短音效单声道。
- BGM 使用可无缝循环的乐句边界；处理尾部/头部残响，不用长静音拼接循环。
- 单个短音效通常 0.06–0.9 秒；长提示/持续激光单独管理，不能占用无限新实例。
- 母版峰值保留至少 6 dB 余量；BGM 与密集音效混合时保留清晰度，降低刺耳高频。
- 导入到 `/Game/Audio/GeometricWarfare`；音频资产列表统一管理，避免代码遍布硬编码路径。
- 短音效预加载并复用播放组件；主曲预加载/预缓存，切换帧不做同步磁盘读取或解码。
- WAV 生成源存于 `Tools/ArenaAudio`；母版存于 `Assets/Audio/GeometricWarfare`。
- 游戏音频由 UE 播放，Unity 宿主继续只负责抖音 SDK，不向匿名管道塞音频 PCM。

## 事件接入与性能预算

当前模拟的 `events`、`damageEvents`、`shots` 都有自身用途和容量，不能仅扫描剩余画面特效来推断枪声。
新增专用的固定容量音频事件收集器，在已存在的发射、伤害、死亡、拾取和 BOSS 攻击代码位置写入。
每个模拟事件写入成本为常数，不新增一次完整 5000 人扫描。
收集器按 18 类音效聚合，每类保留普通与重要来源候选，不为每发子弹分配对象。
一个 UE 帧中多个模拟子步共享聚合结果，在模拟后统一取出并清空；保留短暂的状态变化而不依赖最终 BOSS 快照。

预算与裁剪规则：

- SFX 播放组件池固定 16 个；持续 BOSS 音也计入 16，音乐另计最多 3 个组件。
- 总音效启动速率最多 60 次/墙钟秒，突发令牌上限 8；每个渲染帧最多启动 4 路。
- 普通枪声同类最小间隔 80 ms；普通受击 100 ms；吸球 120 ms；其他普通拾取/死亡 100 ms。
- 主播和关注玩家候选覆盖同类普通候选；筛选不通过额外扫描所有玩家实现。
- 优先级：BOSS 攻击提示/结算退出处理 > 主播/关注玩家 > 击杀/重要拾取 > 其他开火/受击/吸球。
- 低优先级音效不能挤掉持续 BOSS 提示；重要短音可替换较低优先级的音效池槽位。
- 音效音量为 0 时跳过启动和效果解码请求，但仍正确消费/清空音频候选。
- 聚合事件数、启动数、丢弃数、活动音效峰值用于本地测试统计；正式 HUD 不显示开发计数。
- 任何缓存或音频缺失只影响声音，不能阻塞模拟、SDK ACK、分数或对局状态。

## 设置 UI 与保存

在现有设置面板加入“BGM 音量”“音效音量”两个独立可拖动滑条，显示 0–100%。
音量配置放入现有 `UArenaUserSettings`，默认 BGM 55%、音效 70%，边界限定 0–1；非法/NaN 值回到默认。
播放增益使用滑条值平方，让小音量区更易调节；静音为精确 0。
拖动实时更新当前播放的主曲、助战短曲和音效；释放鼠标/触摸时保存，不逐帧写 INI。
滑条接入现有逻辑坐标变换，PC、竖屏、小窗口均可操作；在滑条拖动期间不触发镜头或排行榜操作。
设置面板增加两行并重新排版，保持最小窗口内所有控件可见和可点击。
“恢复性能默认”继续只恢复性能相关项，不改动用户音量偏好。

## 播放与直播收音边界

本地游戏声音由 UE 主程序输出到 Windows 音频设备。
现有 Spout 插件输出共享纹理，音频验收必须独立检查，不能以画面成功作为声音成功的证据。
本地伴侣需要采集 UE 游戏声音/系统音频；测试时使用真实录制确认音乐和音效进入直播画面。
云启动使用平台现有包体音频捕获路径；需要上传候选包后由主播进行真实云启动收音核验。
本地编译、导入、混音录制与压力测试可以先完成；平台云启动收音若没有实际测试机会，交付时明确标记未验证。
不在本次范围新增麦克风权限、网络音频传输协议或 Unity 音频代理。

## 验证与交付

1. 音频资源检查：所有逻辑类别有资产；采样率/声道正确、无静音或截幅、循环边界无明显爆音。
2. 试听：提供三首主曲、助战/结算音乐和音效拼接试听，人工听辨六种武器与三种 BOSS 攻击。
3. 模拟事件测试：六种开火、命中与空枪区别、死亡去重、NPC、球、触碰拾取与打破拾取覆盖真实模拟调用。
4. 音乐状态测试：BOSS 出现/死亡、冲刺优先级、结算、新局、助战压低/恢复及快速切换。
5. 设置测试：独立音量、精确静音、实时改变、重启保存、拖动隔离和 PC/竖屏布局。
6. 5000 人压力测试：同一固定场景、同一模拟参数与音频设备，分别运行开启/关闭音频；覆盖 BOSS 活跃、六种武器和资源事件。
   先预热 5 秒，再采集至少 30 秒；比较帧耗时、模拟耗时、音频调度耗时、播放峰值与事件丢弃数。
   音频调度游戏线程 p95 目标不超过 0.5 ms；活动 SFX 峰值必须 ≤16，不允许随玩家数增长。
   如目标机器未达标，先调播放预算与资源，不减少玩家人数、改变战斗规则或只在关闭音频时报告通过。
7. Editor/Game/Shipping 构建及完整项目测试；正式包验证音频资产已烘焙，加入更新后的操作说明。
8. 保留可复现音频源、原始性能报告和本地录制；交付新的版本包，不覆盖已成功的 1.1.7。

## 已确认范围与限制

- 用户确认范围：5 段音乐、18 类音效、两个音量设置、统一风格、5000 人优化。
- 本设计 pin 的制作参数、播放预算和默认音量是实现基准；可以依据实际试听/压力报告调整后记录。
- 不修改射速、技能、伤害、积分、BOSS 出场秒数、对局时长、直播协议和服务器配置。
- 人工试听与真实直播收音不能由自动化的“资产存在”或“播放函数调用成功”替代。
