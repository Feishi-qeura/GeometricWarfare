# 同账号 PC / 手机直播玩法用户标识不同：平台核验材料

## 问题

几何战争，同一个测试账号（昵称已省略）先在抖音 PC 客户端加入红方，再通过手机进入同一直播间并快捷选队蓝方。
玩法收到两个不同用户键，两端分别控制不同角色，两个角色都计入个人榜，造成账号级阵营锁定和唯一参赛身份失效。

## 环境与链路

- 直播玩法 AppId：`YOUR_APP_ID`。
- 官方 LiveOpenSDK：本地取得的 2.7.12。
- 直播伴侣安装目录版本名：GeomeWar_1.1.9；实际运行的诊断 EXE 哈希已核对。
- UE5.8 通过独立 C# 宿主接 SDK。
- 评论、选队直接取 SDK `Sender.OpenId`；进房取 `SecOpenId`。
  宿主写入事件 `user.open_id`，UE 仅去除两端空白后使用，没有拼接设备 ID 或用昵称生成玩家 ID。
- 角色只由明确的评论加入/快捷选队创建，单纯进房不创建。

手机评论也属于手机进房/选队标识，PC 两条评论属于另一标识。
仅有一次认证房间建立记录，所有对照指纹采用同一会话内的盐；消息指纹各不相同。
指纹仅用于诊断相关性，不是平台可直接反查的原始 ID。
本材料不附启动 token、用户原始标识、SDK envs.log 或账号凭证。

## 希望平台核验

1. 同一账号从抖音 PC 客户端和手机客户端发送直播玩法指令时，是否预期返回不同 OpenId / sec_openid？
2. 是否与观众客户端 AID、平台账号体系或 OpenId 表示格式有关？应采用哪一个规范用户键？
3. 直播玩法是否存在可用的统一用户标识或经验证的跨端映射接口？需要什么权限/SDK 版本？
4. 评论、礼物、点赞、快捷选队以及阵营/排行榜上报应如何保持同一个账号只有一个参赛身份？

官方 FAQ 8.3 提到 uid+appid+aid 生成差异，但例子针对伴侣登录和抖音用户信息接口，
尚未证明适用于本次两类观众客户端：
https://developer.open-douyin.com/docs/resource/zh-CN/interaction/develop/server/live-room-scope/access-faq

## 当前状态

问题边界已定位在进入 UE 时的用户键差异。没有盲目合并同名账号或改动付费武器权益。
真实账号的统一关联方式待平台核验，游戏端修复尚未完成。
