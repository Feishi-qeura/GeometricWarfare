## 交付结构

- `Plugins/LiveInteraction`：平台中立事件、会话、身份隔离、头像、命令与回执。
- `Plugins/DouyinLiveProvider`：当前抖音适配；其他平台实现独立 provider 并注册，无须改游戏的 SDK 依赖。
- `Tools/DouyinSdkHost`：真实官方 LiveOpenSDK 2.7.12 的 Unity 伴随宿主，已通过 BGDT 取得并实际构建。
- `Tools/DouyinLauncher`：根目录凭证启动器，防止令牌进入 UE 启动日志。
- `Plugins/LiveSpoutOutput`：Windows D3D12 的主视口画面共享，包含 Canvas HUD。
- `Services/LivePlatformBackend`：服务端身份换票、周累计、事务归档与顺序上传；[腾讯云 IIS 部署说明](2026-10-05-tencent-iis-deployment.md)。
- `Scripts/Package-DouyinDebug.ps1`：生成完整 Win64 Development 联调目录，并备份/替换原 UE bootstrap 为凭证启动器。

## 本地包启动

```powershell
.\Tools\DouyinSdkHost\Build.ps1
.\Tools\DouyinLauncher\Build.ps1
.\Scripts\Package-DouyinDebug.ps1
```

必须在直播伴侣中选根目录 `output/douyin-live-debug-20261004/Windows/GeometricWarfare.exe`，保留整个目录。不要选内层 `GeometricWarfare/Binaries/Win64/GeometricWarfare.exe`，不要手工把真实令牌放到命令行、聊天、脚本或日志中。

根启动器接受平台的 `-token=...`，以 UTF-8 匿名 stdin 传给 UE；UE 再通过匿名管道把 init 帧交给 SDK 宿主。令牌仍存在于平台启动的根进程 OS 参数中，但不会被转交到 UE/宿主参数或环境变量。官方宿主可能写入环境诊断文件，不能宣称 SDK 完全不写文件。日志只增加房间号、操作名、错误码和状态，不打印原始 SDK 载荷。

正常独立双击应显示等待伴侣启动、0 位观众；这不算鉴权成功。正式已连接需 SDK 返回真实房间及主播身份，游戏开局还需官方 round-start 成功回执。

## 真实联调顺序

1. 在控制台配置有权限的开播测试账号/调试成员，确认直播伴侣技术调试资格。本次核查时调试成员为空；此权限不能由本地代码代替。
2. 用直播伴侣选择根启动器并启动玩法。确认“已连接”和平台对局开始；从 UE 日志 `SDK room connected` 取得 room_id，在自查工具中核对当前房间。
3. 用测试观众发送 `加入`，再选红/蓝；分别核对快捷红/蓝/灰按钮。入队后发 `y/z/c/s`、`武器1`，核对冷却和阵营锁定。
4. 核对真实点赞回血、进入/离开、参与后关注/取关/回关。关注奖励为一次性永久解锁步枪；重复事件或取关重关不能重新刷奖励。旧关注者应先参加玩法，再按进房下发的真实关系判定。
5. 礼物先使用平台认可的测试方式。1.1.16 起，官方 `IsTestData=true`（包含版本审核礼物）正常展示效果并在渲染后履约，不再使用 `AllowPlatformTestGifts` 拦截。测试武器仅在当前会话有效，不写正式权益或自动装备选择；该会话不提交个人战绩、直播间榜单或世界榜，以免测试效果污染正式数据。重新连接并重置战局后开始干净会话。当前没有为用户发起付费送礼。
6. 完成整局，核对每个参与者阵营、结束状态、所有用户战绩、Top150、完成时间和房间榜；失败不得显示为成功。再测断线/重连、延迟回执及退出。
7. 单独核验伴侣画面与官方云启动。云日志页当前保存的是本机 `D:\demo\GeometricWarfare\DoyYinLog`，尚未校正成云节点可用路径；查询还需要测试主播抖音号或 Openid。没有在无标识时伪造日志查询结果。

OpenAPI 自测页本次显示 roomID 为 `-`、0 个角色、未配推送路径。当前 SDK 使用 SinglePush，不需要为了通过页面提示而虚构 HTTP 回调地址。新增的周总榜服务端需要单独启用和安全配置 AppSecret，它只保存在服务器；不能把密钥放进 UE 配置或 SDK 宿主包。

## 验证与限制

本地构建、单元测试、真实 SDK 无凭证协议测试、独立 Spout 接收和云尺寸测试属于不同证据。最终结果以 `docs/verification/2026-10-04-live-integration.md` 和对应 Saved 日志为准。

当前事件去重窗口与已提交 ACK 历史均有界，尚无跨崩溃持久礼物履约账本。结算使用无凭证快照和追加回执，在同平台、应用、房间恢复未完成步骤；跨房不会补交，损坏记录保留并显示阻塞。5000 人及同房恢复已通过本地 UE 回归，实际平台重连仍待验。客户端未完成展示/履约的普通互动与已冻结结算属于不同恢复范围，同进程掉线也需单独验收互动重投。

测试/正式环境切换必须隔离测试存档与待提交结算；outbox 不自动辨识服务器环境开关，具体流程见部署说明。大量用户阵营上报串行执行，平台频控与高人数结算延迟需要真实测试。此包供调试，不应据此宣布已可商业正式上线。
