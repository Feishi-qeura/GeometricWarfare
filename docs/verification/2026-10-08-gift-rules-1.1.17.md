# 1.1.17 仙女棒生命强化与五礼物常驻规则

状态：1.1.17 已完成本地构建、自动化、真实引擎画面、压缩包及包内 Spout 验证。包含五礼物常驻说明、仙女棒本次生命强化、矩形战场、响应式播报、紧凑战报及顶部/榜单积分条。最终 38 项 UE 自动化均成功（1 条引擎联网探测超时警告，非断言失败）；仙女棒套件 164 条断言、矩形相机 116 条断言通过。真实直播间和平台提审仍需外部验收。

## 本次需求

- 仙女棒在本人存活时，每件增加 30 基础最大生命。
- 当前生命增加本次最大生命的增量，保持原受伤缺口，不额外补满当前生命或恢复护甲。
- 生命加成只属于本次存活期间，死亡立即清零；换形保留，换局清零，不写入永久权益存档。
- 本人阵亡时，批量仙女棒的首件用于复活，其余每件增加 30 基础最大生命。不储存额外复活次数。
- 仙女棒仅对已加入的本人生效；冲刺期可以复活及强化，结算期无效。普通礼物不能自动入场。
- 五种礼物的效果和关键限制常驻显示于横屏、竖屏画面，并与即时礼物通知保持一致。
- 根据用户新增截图反馈修复“画面比例变了，关卡比例没变”、战场四周空白过多和播报未随设备适配的问题；保留原世界物理尺寸和玩法规则。

## 生命上限公式与示例

以 `B` 表示本次存活期间累计的仙女棒基础生命加成。存活时收到 `N` 件：`B += 30 × N`。阵亡时收到 `N` 件：首件复活后，`B = 30 × (N - 1)`。

| 状态 | 最大生命 |
| --- | --- |
| 普通观众，未进化 | 形状基础生命 + B |
| 普通观众，进化中 | (形状基础生命 + B) × 2 |
| 英雄，无论是否进化 | 2100 + B |

- 圆形初始最大生命 300，存活时收到 1 件仙女棒后为 330，再获得进化后为 660；进化到期回到 330。
- 普通圆形在进化中收到 1 件仙女棒，其基础最大生命增加 30，进化中的显示上限相应增加 60。
- 受伤圆形当前 / 最大生命为 200 / 300，收到 1 件后为 230 / 330，原有 100 点受伤缺口不变；进化中每件当前 / 最大生命各加 60。
- 英雄初始最大生命 2100，存活时收到 1 件仙女棒后为 2130；获得进化后仍为 2130，护甲上限仍为 300。
- 受伤英雄收到 1 件时当前 / 最大生命各增加 30，当前护甲和护甲上限都不会因存活强化而补充或增加。
- 圆形带加成死亡后 `B = 0`；收到 1 件仙女棒复活后的最大生命为 300。若同一批收到 3 件，首件复活、余下 2 件强化，最大生命为 360。
- 英雄带加成死亡后 `B = 0`，本局英雄资格保留；收到 1 件仙女棒复活后的最大生命为 2100，同一批 3 件则为 2160。
- 进入冲刺前仍然存活的观众成为英雄时保留 `B`；若之前已经阵亡，其加成已在死亡时清零，不能在英雄复活时恢复。

死亡状态的首件仍执行正常复活流程，包括恢复该身份原有的生命和护甲；此后余件使用存活强化规则，不额外补充护甲。这些行为及存活强化的回血反馈已实现，相关纯 C++ 回归通过；最终渲染与正式礼物链路仍按下表分别验收。

## 五种礼物规则

| 礼物 | 常驻规则内容 |
| --- | --- |
| 仙女棒 | 阵亡首件复活；存活及批量余件各加 30 基础最大生命；死亡清零；结算期无效。 |
| 能力药丸 | 红蓝基地已毁时首件重建，剩余每件当前 / 最大生命各加 1000；基地尚存时每件均强化；冲刺 / 结算期无效。 |
| 魔法镜 | 永久解锁并装备左手狙击枪·巴雷特；重复礼物不补弹。 |
| 甜甜圈 | 永久解锁并装备左手机枪·加特林；重复礼物不补弹。 |
| 能量电池 | 永久解锁并装备左手火箭筒；重复礼物不补弹。 |

武器礼物可先保存未入场观众的正式权益，加入后装备；结算期间获得的权益下一局可用。平台测试礼物的武器权益仅限当前会话，测试与正式礼物通知不能合并或在多人汇总时混写为永久解锁。仙女棒、能力药丸继续按实际身份和阶段判定，不为未入场观众创建角色。

## 最新画面反馈与已实现调整

首轮截图揭示了实际布局问题，不能作为最终画面通过证据：`GiftRules-117-Phone.png` 中 390×844 手机战场仅约 64×64 物理像素，三条加入通知几乎完全覆盖战场；`GiftRules-117-NearSquare.png` 保留过多空白；`GiftRules-117-Results-Small.png` 中 854×480 横屏的能量电池描述和公共脚注超出可用区域；`GiftRules-117-PCSmall.png` 中缩小后的桌面礼物栏过窄，脚注掉出屏幕。

矩形战场、礼物说明、播报和紧凑战报已完成下列调整，并通过 19 个主场景及 6 个补充场景的真实引擎渲染复核；最后新增的积分条单独补充验证：

- 战场使用独立的宽度、高度填满规则区、榜单和页脚之间的可用矩形，不再强制用短边生成正方形战场。世界仍为 2000×2000，碰撞、射程、角色尺寸和地图规则不变。
- 相机在两个方向使用同一物理缩放比例，避免圆形或角色拉伸；长轴决定世界跨度，短轴裁剪视野。自由视角可拖动、平移或通过完整世界小地图查看裁剪区域。坐标投影、点击、缩放锚点和边缘限制共用矩形视口计算。
- 五种礼物均常驻。图标移至卡片标题行，功能说明使用整卡宽度；横屏侧栏的三种武器使用紧凑单行卡。死亡清零、进化 / 英雄加成、批量规则、入场和阶段限制由公共脚注明确显示，不通过省略、轮播或滚动隐藏规则。
- 礼物标题字号下限按物理 12px、正文按物理 10px 计算，图标区域至少约 24px；SmallPC 礼物侧栏按至少 300px 物理宽度分配。手机榜单压缩为一行，锁定时增加一行简短详情；召集贴纸缩减空白，仍显示“一键摇人 · 召集好友”和“小摇杆 → 召集 → 发起召集”。原可选规则图片不能覆盖这些常驻内容。
- 紧凑播报使用独立的礼物、奖励、加入队列，各类同时显示一条：礼物和奖励在战场顶部并排，加入消息在底部并避让小地图。宽布局继续使用原多条并行方式。布局切换减少活跃槽位时，将移出条目重置展示年龄后放回原队列前方，当前可见条目不重置占用时长，保留身份、数量及测试 / 正式礼物区分。队列回归及手机三类通知同时出现的截图已通过。
- 紧凑战报按屏幕空间使用四行或两列显示四个奖项、昵称、战绩和下局倒计时。奖项列按实际文字测量宽度留白，避免中文奖项名与昵称重叠；标题至少 18px，正文至少 10px。小地图标题限制在图内宽度，显示“全图”或“锁定”。

实际截图测量：固定 9:16 的 390×844 窗口约 372×216px 战场（固定比例画布外仍等比留边），跟随窗口约 370×334px；1024×1280 近方形窗口约 992×684px。几何角色保持等比。四种紧凑结算画面完整，礼物说明、召集和榜单均未被结算遮挡。

用户随后确认顶部双方总分和榜单观众积分均使用进度条，具体分数在条内居中。顶部以当前较高队伍积分作为共同标尺；榜单以当前第一名积分作为共同标尺，零分保留空轨与数字 0。条形表示当前相对分数，不增加固定积分胜利条件；赛制和结算规则不变。
